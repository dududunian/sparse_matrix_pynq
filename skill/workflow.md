# 可迁移的 PYNQ 加载与验证流程

## 输入契约

运行前由工程提供以下信息，不填猜测值：板卡与器件、镜像/PYNQ/Vivado 版本、匹配 bit/hwh、IP 名称及地址范围、寄存器访问语义、时钟域与经实现验证的频率、复位/空闲条件、输入输出格式和长度、Golden、完成/错误/超时协议。

只运行离线脚本时不需要上述全部硬件字段。进入硬件运行之前必须补齐相关项。

## 操作顺序

1. 在实际 Notebook 内核运行 probe，记录环境；环境导入失败时先确认解释器，而不是立即升级系统包。
2. 离线运行 check_overlay，保留哈希、文件尺寸和检查结果。确认 HWH 与 bit 来自同次构建。
3. 确认目标板可用于此实验后，用该版本 PYNQ 的 Overlay API 加载文件。查看 `ip_dict`，有对应驱动时查看 `register_map`；若自定义 IP 没有可用的 register_map，使用真实地址表和 MMIO，不能猜成 HLS 标准寄存器。
4. 加载 Overlay 可能按 HWH 设置时钟。根据实际硬件时钟树确认目标频率；若需要覆盖频率，应先确保计算核空闲/复位，在启动任务前设置并读回。不能一律使用 `fclk0_mhz`，读回值也不等于外部测量。
5. 按协议读取安全的 ID/状态，再完成小任务。避免读取具有清除副作用的状态位。轮询必须设置超时、记录错误码；完成计数或清除状态用于排除旧完成位。
6. 导出全量结果并调用 compare_golden。不能只看首尾几个数或用 zip 忽略长度差异。根据精度契约选择逐位或容差比对。
7. 无复位连续执行至少两次任务，证明不是旧输出。测试数量应按设计风险增加；两次不是充分覆盖所有边界的保证。
8. 正确性通过后再统计性能。区分加载、传输、计算核周期和 Python 端到端时间。记录板型、频率、输入规模、精度、计时边界和样本次数。

## DMA 扩展适用条件

本包当前没有实现通用 DMA 驱动。若工程有 DMA，需另外确认驱动支持的模式、设备缓冲区、地址/长度/对齐、缓存一致性和 TLAST/TKEEP，接收在产生输出前就绪。数据传输失败时保存通道状态；禁止将普通 NumPy 数组的虚拟地址当作 DMA 设备地址。

## 推荐保存的复用证据

环境 JSON、硬件配置/哈希、真实输入、Golden、原始输出、比对 JSON、运行日志、实现时序/资源报告，以及可从相对路径执行的命令。人工填写下列事实：

| 字段 | 说明 |
| --- | --- |
| task | 实际题目和输入规格 |
| board / device | 实测板卡与器件 |
| image / pynq / vivado | 实际版本 |
| clock | 时钟域、配置/读回与测量方法 |
| source | 仿真、软件例子或真实板卡；证据文件 |
| correctness | 输出长度、比较方法、不匹配数 |
| performance | 计时边界、核内与端到端结果 |
| reuse | 与原题相比替换了什么；是否真实跨设备 |
| limitations | 尚未验证的部分与失效条件 |
